# What logs in where

Which login methods dodo's agent gets through, on your Mac (dodo's Chrome window) and remotely (headless Chromium in Cloud Run). The measured part below is written by `pnpm test:auth` ([AUTH_TESTING.md](AUTH_TESTING.md)); the expectations are what the code and earlier debugging say, until a run confirms or corrects them.

## Expected (from the code, not yet measured)

| Method                         | Local (Mac)                                                                                                                                                                                                                                                                                               | Remote (cloud)                                                                                                                                                                                                                                                                                             |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| itsme (engie.be)               | Works, with you at the Mac: itsme shows a QR code that changes every few seconds, so the agent brings the login to the front in the dodo Chrome window and asks you to scan it there with the app (no picture is sent). A site that still offers the phone-number option sends a push to the app instead. | Not here: nobody can scan a QR code that changes every few seconds in the cloud browser, so the agent calls `request_device` as soon as itsme comes up and the task continues on the Mac (at once with Device = Auto; after a yes on the card when pinned to Remote). Expected result: works after moving. |
| Google (vinted)                | Works in the real Chrome window via "Continue with Google"; the 2-step prompt goes to your phone. You are needed at the Mac when Google offers a passkey, Touch ID or a security key, or shows a CAPTCHA.                                                                                                 | Not here: Google refuses the cloud browser, so the agent calls `request_device` as soon as the site needs a Google sign-in and the task continues on the Mac. Expected result: works after moving.                                                                                                         |
| Username + password (overleaf) | Works: the agent types from the vault. Overleaf may show a CAPTCHA, which then needs you at the Mac.                                                                                                                                                                                                      | Works: this is the one login the cloud browser does, with the site's vault entry (and its emailed, SMS or authenticator code). A CAPTCHA or a refusal moves it to the Mac.                                                                                                                                 |
| Email + 2FA (booking.com)      | Works: the agent enters your email address (personal info, or the vault entry if you have one). Emailed codes are fetched from Gmail (`get_email_code`); SMS codes and authenticator codes are asked as secret answers (TOTP from the vault is not built yet).                                            | With a `booking.com` vault entry: works, the code comes from Gmail. Without one (the default): not here, the agent calls `request_device` and the task continues on the Mac.                                                                                                                               |

Where a login needs you at the Mac rather than on your phone, see [AUTH_TESTING.md](AUTH_TESTING.md#when-you-have-to-be-at-the-mac).
